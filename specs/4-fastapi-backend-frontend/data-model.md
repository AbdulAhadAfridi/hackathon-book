# Data Models: FastAPI Integration

## Core Entities

### ChatRequest
- **Fields**:
  - `query`: str (required) - User's question or query text
  - `selected_text`: Optional[str] - Optional text selected by user for additional context
- **Relationships**: Input to the chat endpoint
- **Validation**: Query must be non-empty, length limited to prevent abuse

### ChatResponse
- **Fields**:
  - `response`: str - The answer generated by the RAG agent
  - `sources`: List[Dict] - Citations to source materials used in the response
  - `processing_time`: float - Time taken to process the request in seconds
  - `timestamp`: str - ISO 8601 timestamp of the response
  - `query_id`: str - Unique identifier for the query
- **Relationships**: Output from the chat endpoint
- **Validation**: Response must be non-empty, sources should be properly structured

### ErrorResponse
- **Fields**:
  - `error_code`: str - Machine-readable error code
  - `message`: str - Human-readable error message
  - `details`: Optional[Dict] - Additional error details for debugging
  - `timestamp`: str - ISO 8601 timestamp of the error
- **Relationships**: Output from the API when errors occur
- **Validation**: Error code and message must be present

## State Transitions

### Request Processing Flow
1. **Request Received** → Input validation using Pydantic models
2. **Valid Request** → Query context preparation
3. **Context Prepared** → RAG agent processing
4. **Agent Response** → Response formatting and metadata enrichment
5. **Formatted Response** → Return to frontend
6. **Error Occurred** → Error response generation

### Error Handling States
- **Invalid Request**: Return 400 Bad Request with validation errors
- **RAG Agent Unavailable**: Return 503 Service Unavailable
- **Processing Error**: Return 500 Internal Server Error
- **Timeout**: Return 408 Request Timeout

## Validation Rules

### From Requirements
- **FR-001**: API endpoints must be accessible and accept user queries
- **FR-002**: Queries must be routed to RAG agent for processing
- **FR-003**: Responses must be in structured JSON format
- **FR-004**: API must handle selected text context properly
- **FR-005**: API must return appropriate error responses when RAG agent is unavailable
- **FR-006**: API must validate input parameters and return appropriate errors
- **FR-007**: API must process queries asynchronously to avoid blocking
- **FR-008**: API must include response metadata such as processing time and citations

### Data Integrity
- All text fields must be properly sanitized
- JSON responses must be valid and parseable
- HTTP status codes must align with response content
- Timestamps must follow ISO 8601 format
- Error responses must contain appropriate error codes
